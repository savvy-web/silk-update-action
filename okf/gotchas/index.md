# Gotcha

* [A caret on a 0.x dependency pins the minor, and pnpm never revisits a satisfied range](caret-pins-minor-on-0x.md) - pnpm install exits 0 while silently leaving a 0.x dependency on an old minor, because a caret range that is already satisfied is a range pnpm never re-resolves.
* [A clean pnpm-lock.yaml is not evidence of the peer-suppression rules in effect](lockfile-omits-peer-rules.md) - pnpm-lock.yaml records what config-dependency pnpmfile hooks did to resolution (overrides) but not their reporting-only effect (peerDependencyRules), so reading the lockfile or pnpm-workspace.yaml alone will not find rules that are genuinely in force.
* [A duplicate kit package and a type error are not necessarily cause and effect](duplicate-kit-copies-and-stale-transitives.md) - Two resolved copies of an @effected package look like the obvious explanation for a type error touching its exported type, and measurement has shown that reading to be wrong.
* [A fixture that forgets to seed its own state decodes the host workflow's persisted data and passes](runner-env-leaks-into-tests.md) - Without vitest.setup.ts stripping runner-owned env prefixes, ActionState.get can succeed against real STATE\_\* pairs left by the CI job running the test, so a test passes for the wrong reason and only under a real runner.
* [A green coverage run is not evidence a module is exercised](aggregate-coverage-gate.md) - The coverage gate enforces aggregate, whole-run minimums, not a per-file floor, so an entire module can have zero test execution while the suite stays green.
* [A just-published npm version can be unresolvable for minutes after publish succeeds](npm-scan-holds-a-published-version.md) - npm's publish-time malware scan can hold a freshly published version back from the registry for minutes while the publish itself reports success; an update run triggered off that publish fails the install with ERR\_PNPM\_NO\_MATCHING\_VERSION (or npm ETARGET, bun "No version matching"), which reads as a wrong range but is transient. The action retries that one failure on the retry-unmatched schedule; the wait counts against timeout.
* [A miscompiled computed dynamic import passes every check except the built bundle](context-module-only-breaks-in-prod.md) - rspack rewriting a runtime-computed import() into a webpack context module typechecks, lints, and passes the whole vitest suite, because vitest runs the TypeScript source rather than dist/main.js — the failure exists only in the artifact nothing but a build-time script inspects.
* [A search that cannot read a file returns nothing, indistinguishable from a real no-match](unreadable-file-reads-as-no-match.md) - grep silently skips a file it detects as binary, and that empty result looks identical to a genuine absence — src/services/lockfile.ts once carried a raw NUL byte that made grep skip all 531 lines and an audit report the file clean.
* [A test double stricter or richer than production hides the bug it should catch](double-more-capable-than-production.md) - A double that fails harder or knows more than the real service it replaces produces a green suite for the wrong reason — too strict invents a bug in correct code, too capable hides a wiring bug in the code under test.
* [An Effect Schema base-class rename presents as dozens of unrelated call-site errors](tagged-error-rename-presents-as-call-site-errors.md) - When an Effect v4 prerelease renames a Schema class-factory base, the resulting typecheck failures overwhelmingly name call sites that never touch the renamed API, because the base type collapsing is what breaks every constructor and field getter built on it.
* [An abstained peer report reads exactly like a repo with real peer problems](peer-check-abstain-looks-like-peer-problems.md) - check-peers withholding auto-merge with zero required rows is indistinguishable, from the consumer side, from a repo with unsatisfied peers — both simply withhold auto-merge, and two real pnpm lockfile shapes triggered the abstention on genuinely clean repos.
* [An excluded test file is silently never collected — the suite shrinks and stays green](uncollected-test-suite.md) - A \*.test.ts placed under a reserved helper directory name is dropped from the run with no error and no warning; the total drops and the aggregate coverage gate has no way to notice.
* [An unprovided service in makeAppLayer is not a type error](unprovided-service-is-not-a-type-error.md) - Action.run's optional options parameter lets a leftover requirement in makeAppLayer's channel typecheck cleanly and die on the runner as a defect.
* [Run.text trims its output, which corrupts a column-aligned format](run-text-trims.md) - @effected/commands' Run.text silently trims leading and trailing whitespace, shifting every subsequent index in fixed-width or column-aligned text; this repository no longer parses such formats, but the trap is live for the next caller that reaches for Run.text over one.
* [This repository's @effected ranges come from a config dependency, not package.json](kit-ranges-come-from-a-config-dependency.md) - package.json declares every @effected/\* range as a catalog reference; the actual version ranges live in a pnpm config dependency's published catalog, pinned one level away in pnpm-workspace.yaml.
