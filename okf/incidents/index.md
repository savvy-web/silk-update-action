# Incident

* [A memoized WorkspaceCatalogs assembly judged the after-install lockfile under pre-install rules](peer-rules-time-skew.md) - Release-age discovery triggered WorkspaceCatalogs' memoized assembly before the install; the same run bumped the config-dependency plugin whose allowedVersions suppress the reported row, so peer-check judged the after-install lockfile under the pre-install plugins' rules and withheld auto-merge on a suppressed row.
* [A pnpm 11 to 12 upgrade committed a lockfile pnpm 12 refuses](pinned-package-manager-not-activated.md) - The upgrade step rewrote the pin to pnpm 12.4.2 and the install then ran under the pnpm 11 shim the runtime action had put on PATH at job start, so the committed lockfile carried a v11 pnpmfileChecksum that pnpm 12 rejects with ERR\_PNPM\_LOCKFILE\_CONFIG\_MISMATCH.
* [The first check-peers dogfood run died on an unmerged WorkspaceCatalogs](workspacecatalogs-not-merged.md) - steps/peer-check.ts resolved WorkspaceCatalogs in its own step body rather than a layer body; makeAppLayer built the layer and piped it into ReleaseAge alone without merging it into the layer it returns, so the requirement never entered the layer-side guard's input channel.
* [Two real pnpm lockfile shapes made peer-check abstain on a clean repo](peer-check-abstained-on-clean-repo.md) - Under @effected/lockfiles at or below 0.6.1, npm-alias dependencies and publishDirectory link: edges both landed in ResolvedPackage.unresolvedEdges, flipping the peer report to unverified and withholding auto-merge from a repository with zero real peer problems.
* [v4.6.0: every consumer run died on an unprovided PackageJsonFile](v4-6-0-packagejsonfile-unprovided.md) - PackageManagerUpgrade.layer began resolving PackageJsonFile in its layer body; makeAppLayer provided that service to RuntimeUpgrade.layer only, and the leftover requirement typechecked cleanly under Action.run's optional layer argument.
