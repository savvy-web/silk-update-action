# Decision

* [A first-party computed dynamic import stays local, guarded by a build-time assertion](dynamic-import-stays-local.md) - The one dynamic import this action itself performs — loading a config dependency's extracted tarball entry — cannot be declared to the bundler's nativeDynamicImports list, so it carries an inline webpackIgnore comment instead, verified against the built dist/main.js after every build.
* [Adopt @effected/git for all local git operations; pin core.fileMode in repository config](git-status-only-filemode-in-repo-config.md) - Every local git operation this action performs — status reads and the mutating tier alike — now goes through @effected/git; core.fileMode=false is written once into the checkout's repository config rather than passed per command.
* [Adopt @effected/package-json for surgical field edits only, never its decode path](package-json-modify-only.md) - Both manifest writers (RuntimeUpgrade, PackageManagerUpgrade) apply changes through PackageJsonFile.modify, a JSONC span edit; both still read with readFileSync + JSON.parse because the package's schema-decoding read path rejects a private workspace root.
* [Build on Effect v4 and the @effected kit, not plain TypeScript or one all-in-one library](effect-v4-and-effected-kit.md) - Why domain logic is Effect services over Context.Service/Layer, and why the action depends on the split @effected/\* kit rather than the deleted all-in-one @savvy-web/github-action-effects.
* [Commit via the Git Data API with no author, sign off separately from the token identity](github-app-and-verified-commits.md) - Why commits omit an explicit author (that is what makes GitHub verify them) and why the DCO Signed-off-by trailer is a separate, deliberate concern resolved from the persisted App token rather than a literal.
* [Delegate dependency changesets to silk-effects' DepsRegen](delegate-changesets-to-depsregen.md) - The changeset step is a thin adapter over @savvy-web/silk-effects' Changesets.DepsRegen, which owns the diff, consolidation and gating; this action carries no changeset predicate of its own.
* [Detect the package manager once, and dispatch every step on it](detect-package-manager-once.md) - The workspace root and package manager are resolved a single time per run; every later dispatch point reads that one value instead of re-detecting.
* [Do not adopt @effected/github-references — there is no call site for it](github-references-not-adopted.md) - The issue-reference-parsing package arrives transitively already; this action has nothing to parse or write, because a dependency-update run closes no issues.
* [Each orchestration step declares its own error channel](steps-own-their-error-channels.md) - A step carries a tagged error in its type only if it can actually fail; five of sixteen steps are typed never, and program.ts composes rather than performs I/O.
* [Force-reset a dedicated branch every run rather than rebase](dedicated-branch-reset.md) - Why the update branch is validated then force-reset to the source ref on every run instead of merged or rebased forward.
* [Guard makeAppLayer's requirement channel at compile time, not by convention](compile-time-layer-guard.md) - Two type-level assertions in a test file — not a runtime check anywhere in the production call path — are what stop an unprovided service from shipping as a defect on the runner.
* [Keep a lockfile-snapshot read failure fatal, for now](keep-lockfile-snapshot-fatal.md) - LockfileError from the before/after lockfile snapshot still fails the job, even though a case exists for degrading it to a diagnostic null, because that change was never isolated from the extraction it surfaced alongside.
* [Keep every unit suite under \_\_test\_\_/unit, mirroring src, never co-located](tests-not-colocated.md) - No .test.ts file lives beside its source; the mirror layout has a cost (a reserved-directory footgun that silently drops a suite from collection) but co-location had a worse one — importing a fixture module re-executed its tests.
* [Keep persistLocal disabled](persist-local-disabled.md) - The builder's persistLocal option, which would commit a duplicate copy of dist/ into .github/actions/local for an act smoke-test loop, stays off because nothing in this repository runs act.
* [Keep the run's log rendering and the PR's report rendering as two separate modules](format-and-report-stay-separate.md) - format.ts renders the run's log output and report.ts renders the PR body, summary and commit message — two named rendering modules split by sink, not a rule violated by having two.
* [Leave platform services in makeAppLayer's requirement channel instead of building private copies](platform-stays-in-requirement-channel.md) - makeAppLayer never constructs FileSystem, Path, HttpClient or ChildProcessSpawner — every layer that needs them leaves the requirement in the returned layer's input channel for Action.run's own runtime to satisfy, so the bundle never carries a second copy of the Node platform.
* [Publish the output baseline before any work runs](emit-output-baseline-first.md) - Every declared output is set to a safe value as the first statement of the program, not from a failure handler, so no exit path ever leaves one unset.
* [Refresh WorkspaceCatalogs before reading peer-suppression rules](refresh-catalogs-before-peer-check.md) - The peer-check step forces a fresh config-dependency hook replay so it judges the after-install lockfile under the after-install rules.
* [Regenerate the lockfile from a clean slate rather than repair it in place](regenerate-lockfile-not-repair.md) - Why runInstall runs a clean-and-reinstall sequence per package manager instead of a repair-only install, and why the npm path removes the lockfile via node:fs instead of a shelled rm.
* [Release-age gate discovery fails open](release-age-fail-open.md) - A gate that cannot be assembled degrades to no gate with a warning, because pnpm re-enforces minimumReleaseAge at install regardless.
* [Resolve dependency updates within the declared range, never to npm's absolute latest](resolve-within-declared-range.md) - ConfigDeps and RegularDeps synthesize or reuse a conservative range and pick the highest version satisfying it, rather than jumping to whatever npm reports as latest.
* [Route a bun catalog merge on WHY the base tarball could not be read, never collapse every failure to one outcome](catalog-base-routing.md) - CatalogConfigDeps' three-way merge picks one of four routes depending on the specific reason the base version's catalogs export could not be read; collapsing those reasons into a single null previously discarded a user's override on a run that reported success.
* [Run as three phases around a GitHub App token, not a personal access token](three-phase-token-lifecycle.md) - Why the action provisions a short-lived installation token in pre, consumes it in main, and revokes it in post — always — rather than reading a long-lived PAT once.
* [Runtime upgrades only ever upgrade an existing entry, and always write a bare exact version](runtime-upgrade-only-exact.md) - RuntimeUpgrade never adds a devEngines.runtime entry a manifest lacks, and it never writes a range operator back — both rules hold in every mode, because a downstream consumer cannot accept either.
* [The peer-dependency auto-merge gate fails closed](peer-gate-fails-closed.md) - Auto-merge is withheld whenever the peer report cannot be proven clean, not only when it proves a problem.
